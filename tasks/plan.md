# NovaSight 用户诉求收尾计划

目标：按当前代码和运行态逐项关闭尚未证明的诉求。源码、模拟浏览器、隔离 Jetson、真实画面和物理输出分别记账；任何较窄证据不得替代较宽验收。

## 决策与边界

- 先修可在工作区完成的地图、模型管理和前端交互，再统一进行一次快速本地验证；避免每个改动重复跑整套测试。
- 模型文件路径是部署身份的一部分。创建目录和移动/重命名必须经过后端安全校验、活动部署保护、同目录 manifest 处理和读回，不能只在浏览器改路径。
- Jetson 隔离测试使用配置副本，`output_enabled=false`、`auto_connect=false`，不启动当前用户配置，也不发送诊断移动。真实物理输出另需在有人监督的设备验收中进行。
- 公平性仅做异常识别、输出阻断和 dry-run 证据，不加入伪装、模仿人类或规避判定的运动策略。
- 每项任务的验收、依赖和验证见 [todo.md](todo.md)。任务 1、2 可先行；3 依赖 2；模型操作先后端后前端；运行态证明依赖代码与构建。每完成 2–3 项做一次检查点，最终统一全量验证。

## 任务索引

1. 工作空间内的算法责任与公平性自检地图，替换过期快照证据。
   已确认的准星超时回退缺口在这一项内修复并留回归检查。
2. 15 个逐条可复现的前端问题台账，按真实/模拟证据分层。
3. 修复台账中仍存在的问题并复测相应交互。
4. 模型目录创建从安全后端到前端读回的完整交互。
5. 模型文件移动/重命名从路径事务到前端确认的完整交互。
6. 模型库操作后的跨页面一致性与失败恢复验收。
7. 当前提交的隔离 Jetson 页面—网关—后端—配置读回验收。
8. 真实非空目标的采集→GPU 检测结果验收，含选定规格。
9. 公平性阻断与现场输出验收，以及最后的文档、CI、同步审计。

## 检查点

- 任务 1–3：地图证据路径可打开，15 项每项有复现/结论，前端快速测试与桌面/窄屏浏览器检查通过。
- 任务 4–6：每个文件操作自身贯通 API 与页面；拒绝越界/活动模型，成功与失败后 UI、目录和持久配置一致；不得因路径变更丢失 manifest。
- 任务 7–9：按提交 SHA 分别保留主机、Jetson 隔离、真实非空场景和物理输出收据；无法取得的收据标为未完成。

## 风险

- 实机没有运行包或真实目标画面：先完成可安全构建与隔离验证的部分；不把空检测或模拟页面算作现场通过。
- 活动模型路径变化：默认拒绝，除非单独实现可回滚部署事务并取得相应验收。
- 旧文档和可视化引用过时：以当前源码位置与 SHA 复核，修复引用后才标记完成。
