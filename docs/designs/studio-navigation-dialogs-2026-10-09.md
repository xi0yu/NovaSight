# Studio 导航与应用弹窗边界

业务菜单顺序：首页 → 设备管理 → 算法参数 → 开火稳定 → 实时日志 → 鼠标协议。设置、关于属于底部应用菜单，不加入主工作区的页面状态。内置布局和发布用 studio-layout.json 同步排序；旧布局把鼠标协议排在前面时，导航组件仍将输出入口放到业务区最后。侧栏内容保留完整高度，短窗口通过侧栏滚动访问，避免业务按钮与底部菜单重叠；手机使用同一职责分组的横向导航。

| 入口 | 职责 | 展示位置 |
| --- | --- | --- |
| 首页 | 主链启停、当前运行结论与指标 | 业务页 |
| 设备管理 | 采集、ROI、模型、推理与性能入口 | 业务页及相关深层页面 |
| 算法参数 | 日常控制参数与进阶控制调校 | 业务页及 control 深层页面 |
| 开火稳定 | 近目标开火时的稳定参数 | 业务页 |
| 实时日志 | 运行记录与操作结果 | 业务页 |
| 鼠标协议 | 输出协议注册、配置、启用取消与连通性测试 | 业务区最后的独立页面 |
| 设置 | 整份配置的备份与恢复 | 底部入口打开弹窗 |
| 关于 | 版本、能力、支持和授权入口 | 底部入口打开弹窗 |

StudioConsoleView 保持配置与导航的既有业务所有权；ConsoleWorkspacePage 在类型上排除 settings/about。StudioUtilityDialog 只负责显示容器、背景交互隔离、Tab 焦点约束、Escape/遮罩关闭和关闭后的焦点恢复；SettingsView、AboutView 保留各自内容及操作回调。主业务页始终保留在 DOM 中，打开应用弹窗不会改 URL、卸载页面、丢失草稿或重置滚动。弹窗内选择授权或日志时，关闭弹窗并进入真实对应工作区。

旧 ?page=settings / ?page=about 深链初始化为首页上的相应弹窗，并规范为首页 URL；历史记录中的旧入口打开弹窗并保留当前业务页。导航按钮使用 aria-haspopup=dialog 和 aria-expanded，不冒充 aria-current=page。

配置恢复继续沿用现有读取、revision 校验、差异确认、保存队列、运行时应用及物理输出保护；取消嵌套导入确认返回设置弹窗。设备状态中的输出入口进入鼠标协议；进阶控制页归属算法参数。

验证：61 项定向单元、53 项完整桌面/手机浏览器检查通过，TypeScript、Vite 构建和 diff 空白检查通过。检查覆盖菜单分组与排序、低高度侧栏、手机横向导航、弹窗焦点循环、关闭与导航返回、草稿及滚动保留、旧 URL、配置恢复取消后重新确认、模型编辑保护及授权退出。没有连接实物设备、改写已有用户配置、提交或发布。
