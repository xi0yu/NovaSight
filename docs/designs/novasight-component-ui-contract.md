# NovaSight Studio 控件级 UI 与动态页面契约

状态：实施基线
外观：Graphite Signal（单一产品外观）
原则：状态先于原因，原因先于技术细节；页面围绕任务，不围绕内部包名。

## 1. 页面骨架

Studio 的一级入口固定为五类用户任务，但名称、顺序、模块顺序和模块显隐可由部署侧配置：

1. 首页
2. 设备管理
3. 算法参数
4. 实时日志
5. 关于

模型管理、推理详情、性能、控制测试和授权仍是完整页面，但由当前模型、设备状态、新手任务或关于页进入，不再形成第二套隐藏导航。

全局壳层只有三类持续控件：

| 控件 | 用途 | 交互 | 刷新 |
| --- | --- | --- | --- |
| 当前模型入口 | 显示正在使用的模型并进入模型工作区 | 单击进入模型管理 | 模型切换成功、运行快照更新 |
| 当前输入入口 | 显示 `/dev/*` 或采集来源并进入设备管理 | 单击进入采集设置 | 保存配置、运行快照更新 |
| 实时状态与故障入口 | 显示连接新鲜度和待处理故障数 | 单击打开异常详情 | WebSocket 推送，局部更新数字和状态 |

不提供主题选择器。外观属于产品，不是要求用户做出的配置决定。

## 2. 控件原语

所有页面只能组合以下交互原语，不能在业务页临时发明另一套按钮或状态样式。

| 原语 | 组成 | 状态 | 约束 |
| --- | --- | --- | --- |
| 主操作按钮 | SVG 图标、动词、进度反馈 | idle / hover / pending / success / disabled | 每页最多一个视觉主操作；高度不小于 40px |
| 次级按钮 | 图标、短动词 | idle / hover / disabled | 不和主操作同权重 |
| 状态标签 | 状态点、短文本、可选说明 | live / normal / waiting / warning / error / unavailable | 颜色不能单独承载含义 |
| 实时指标 | 名称、等宽数字、单位、样本状态 | live / stale / unavailable | 没有样本显示“等待样本”，禁止伪造 0 |
| 任务行 | 图标、对象、当前状态、一个行内动作 | normal / attention / disabled | 行本身可导航，动作必须明确 |
| 参数控件 | 标签、说明、输入、单位、生效方式 | clean / editing / dirty / saving / applied / error | 修改后就地反馈，不吞掉后端错误 |
| 模块开关 | 名称、说明、switch | on / off / pending / blocked | 可访问名称描述结果，不只写“开/关” |
| 等级筛选 | 标签、数量徽标 | selected / unselected | 筛选只影响本地列表，不阻断日志接收 |
| 信息流条目 | 等级标签、标题、人话说明、时间、技术详情 | info / success / warn / error | 默认展示人话，技术证据用 disclosure 展开 |
| 确认弹窗 | 结果、影响、取消、确认 | open / pending / error | 只用于外部副作用或不可逆操作 |
| 诊断 disclosure | 摘要、证据键值、原始日志 | closed / open | 默认收起，不抢占第一屏 |

## 3. 首页

主要目的：五秒内回答“现在是否正常、正在做什么、下一步是什么”。

### 模块 `setup`

- 新手任务提示：完成数、下一步、继续设置按钮。
- 仅未完成初始化时出现；完成后自动消失。
- 单击继续进入第一项未完成任务，不重置已经完成的步骤。

### 模块 `runtime`

- 当前设备标识。
- 总体运行结论。
- 下一步恢复动作。
- 唯一运行开关：运行时显示“停止运行”，停止时显示“运行”。
- 点击后立即进入 pending，收到运行快照后确认最终状态；失败写入实时日志并保留原因。
- 不再额外展示“紧急停止”作为第二关卡。

### 模块 `metrics`

- 推理输入 FPS。
- 检测结果 FPS。
- 推理耗时。
- 结果帧龄。
- 数字使用等宽字体和 tabular figures；WebSocket 快照只更新数值节点。
- 状态过期时整组显示“状态已过期”，不保留看似实时的旧数字。

### 模块 `pipeline`

- 默认首页不展示；由部署配置或专业详情按需启用。
- 使用文字状态列表展示：采集 → 感知 → 目标 → 输出。
- 每个节点根据真实状态显示 live / idle；不再同时维护一套装饰性 SVG。
- 运行、识别、输出三条结论独立显示，避免把“算法算出结果”误写成“物理设备已经执行”。

### 模块 `diagnostics`

- Daemon 实例、快照序号、Studio 接收时间、kmNet 连接、当前样本输出门。
- 默认收起；用户主动展开时才阅读。

## 4. 设备管理

主要目的：选对真实输入、真实采集规格、模型和 ROI，并核对运行态是否采用。

### 模块 `source`

- 保存规格与运行规格对照条。
- 摄像头设备输入。
- “读取可用规格”按钮。
- 规格选择器。
- “使用这个画面规格”主按钮。
- 预览帧率选择。
- 读取能力只在用户点击后发生；更换设备会清除旧能力结果，避免把旧采集卡规格误当成新设备规格。
- 应用过程显示 pending；保存失败、刷新失败分别展示原因。

### 模块 `roi`

- ROI 大小步进控件。
- 常用尺寸快捷选项。
- 源画面与运行 ROI 对照。
- 编辑期间保留当前输入，WebSocket 高频更新不能抢走用户正在输入的值。

### 模块 `model`

- 当前模型名称。
- 运行态是否已装载。
- “管理模型”入口。
- 模型工作区提供目录、命名排序、版本、资格验证、部署状态和切换确认；切换失败保留上一可用模型。

### 模块 `diagnostics`

- 采集原因、设备、参数来源、输入格式、分辨率、帧率、运行 ROI。
- 推理输入 FPS、统计窗口和指标可用性。
- 没有后端指标时明确写“当前服务未提供”，禁止用前端估算值替代。

## 5. 算法参数

主要目的：按实际使用顺序调整参数，并持续知道“是否已保存、是否已生效”。

### 固定反馈控件

- 输出状态标签。
- 保存状态条：clean / dirty / saving / applied / error。
- 保存并应用、放弃修改、导入、导出。
- 导入前存在未保存修改时阻止覆盖；导出只导出后端已保存版本。

### 模块 `response`

- 触发延迟数值，`0 ms` 表示立即执行。
- 目标速度预测开关。
- 算法参数弹窗入口。

### 模块 `motion`

- 压枪开关。
- “仅有目标时”条件开关。
- 间隔和 Y 补偿。
- X/Y 输出限幅。
- 页面内普通控件统一保存并应用，不逐项弹窗。

### 首页运行控制

- 唯一“运行总开关”只出现在首页。
- 打开后执行采集、推理和控制；关闭后只保留前后端通信。
- 开启前展示设备影响确认；参数保存不会改变运行状态。

### 模块 `targeting`

- 单一类别配置入口，不展示命名版本或预设管理。
- 目标选择半径。
- 六项选择评分摘要和权重入口。
- 短时关联与跟踪专家设置。
- raw cls 只是本帧证据，不作为永久身份。
- 参数弹窗的“保存并应用”直接写入设备并等待后端确认；失败时保留窗口和输入，不再制造“加入草稿后再保存”的第二步。

### 模块 `advanced`

- desired / effective 配置版本。
- 未生效项目与建议动作。
- 默认折叠，不干扰普通调整。

## 6. 实时日志

主要目的：让用户和开发者都能找到真实错误，同时不把堆栈直接砸在用户脸上。

### 模块 `summary`

- 当前待处理数量。
- 清晰的人话结论。
- 存在故障时显示“查看完整详情”。

### 模块 `filters`

- 全部、故障、警告、完成、信息。
- 每个筛选带实时计数徽标。
- 筛选在浏览器本地完成；新的 WebSocket 条目到达后，当前筛选保持不变且列表局部更新。

### 模块 `feed`

- 等级标签。
- 标题和用户说明。
- 重复次数。
- 时间。
- 原始错误与开发者详情 disclosure。
- 相同来源和详情可聚合计数，但不能吞掉最新一次时间和 request id。

## 7. 关于

主要目的：展示产品身份、连接情况、版本、能力边界和支持入口。

### 模块 `identity`

- NovaSight 标志 SVG。
- 产品名称和一句话说明。
- 服务连接状态。

### 模块 `version`

- Studio 版本。
- 当前页面配置 revision。
- 授权层级。

### 模块 `capabilities`

- 采集与 ROI。
- 模型与推理。
- 目标与跟踪。
- 控制与输出。
- 每项使用统一 SVG 图标，不使用与数据无关的小图片。

### 模块 `support`

- 查看授权。
- 打开实时日志。

## 8. 新手流程

新手页不占一级导航。未完成初始化时由首页任务提示进入：

`连接画面 → 选择模型 → 确认参数 → 回首页启动`

每步读取真实后端状态；离开再返回时从第一项未完成任务继续。失败后保留用户意图和已完成步骤。

## 9. 动态页面配置

部署目录中的 `web/public/studio-layout.json` 是运营配置入口。网页每 30 秒以 `no-store` 方式刷新，成功校验后只替换导航和模块布局，不刷新整个页面。

允许动态配置：

- 五个已知页面的顺序与显隐。
- 页面显示名称。
- 已知模块的顺序与显隐。
- 配置 revision。

明确禁止：

- 远程 HTML、JavaScript、CSS。
- 远程 API 地址或任意动作名。
- 未注册页面和未注册模块。
- 删除首页。
- 重复页面或重复模块。

配置无效或网络失败时保留上一次已验证布局；首次失败使用内置完整布局。这样运营可以调页面结构而无需重新构建客户端，同时不会把远程配置变成代码执行入口。

## 10. 局部刷新矩阵

| 数据 | 来源 | 更新方式 | 影响范围 |
| --- | --- | --- | --- |
| 运行状态、FPS、耗时、帧龄 | novasightd WebSocket | 状态快照 | 首页指标、信号图、设备状态 |
| 操作完成与前端异常 | 会话通知流 | 事件追加/聚合 | 实时日志和故障徽标 |
| 模型与配置状态 | API + 运行快照 | 操作后刷新并等待运行态确认 | 当前模型、模型工作区、参数状态条 |
| 页面布局 | `studio-layout.json` | 30 秒轮询 | 导航、模块顺序和显隐 |

任何局部刷新都不得：抢走输入焦点、覆盖正在编辑的草稿、重置滚动位置、关闭用户主动打开的详情，或把旧数据重新标成实时。
