# 授权与登录恢复契约

状态：冻结 v2，2026-10-10。适用于 Web 网关、daemon 授权、浏览器鉴权、部署和验收。

## 裁决与修改权限

本文件是实现和验收的裁判。工单必须引用规则编号；出现未定义行为，先修改本文件及反向验证，再写代码。实现不得以技术方便降低规则。冻结不表示实现已经完成。修改本文件须记录原因、影响的工单和回归场景。

## 不变量

- A01：用户授权一次，在真实授权有效期内，短期凭证到期完全不可见。不跳页、不弹窗、不投递会话到期 toast、不清空输入、不显示第二个到期时间。
- A02：长期续期凭证绝对期限不得超过签发时机器授权期限；访问凭证同样受此期限约束。续期、重新登录和正常服务重启均不能延长原授权。内测版空码申请的授权期限为服务端首次收到申请后 24 小时；有效期内重复空码申请沿用原授予，不能重置一天；已激活的测试授权在普通服务重启后保留原期限，不产生新一天。
- A03：只有浏览器持有有效凭证才能恢复身份。机器已有授权不是匿名访问的登录凭证。内测版用户主动提交空授权码是申请行为，由服务端确认授予后建立双凭证；GET/refresh 不申请新的机器授权。Cookie 清除、明确撤销、主动退出是不能静默恢复的例外，必须由服务端确认原因或由用户退出操作触发。
- A04：网络超时、502/503、WebSocket 断开、重试耗尽、普通重启、客户端时钟和本地计时器都不能判定终态。仅进入待确认或重连中。
- A05：恢复身份不等于业务可用。重连后核对真实授权、运行、配置、模型、设备状态。旧数据可保留，但不得冒称已确认。不得自动启动采集、推理或物理输出。
- A06：业务请求的鉴权拒绝必须发生在执行之前，返回明确的 AUTHENTICATION_REQUIRED 或 CSRF_REJECTED。仅这两种拒绝可在身份恢复后重试一次。网络超时、响应读取失败、其他 401/403、未知执行结果的写操作不得自动重放；一次性硬件控制指令不得自动重放。
- A07：同一页面 HTTP、计时器、可见性恢复、WebSocket 共用一个刷新 Promise。多标签页协调刷新；服务端原子轮换及短时重复请求兼容保证不互踢。旧请求的失败不能覆盖新身份结果。主动授权期间恢复请求等待同一授权结果；用户退出后，迟到的授权或刷新响应均不得恢复身份。
- A08：机器授权真实失效由 daemon 阻止并停止资源服务，保留前台。浏览器登录凭证失效或主动退出不等同于机器授权失效，不伪称已经停止后台。
- A09：远程提供静态构建，Vite/HMR 仅本地。版本变化只提示，用户选择刷新；未保存内容须在刷新前保护；旧带 hash 资源保留以服务已打开的页面。构建先写独立临时目录，资源发布完成后原子替换入口，最后发布版本提示；不能让正在读取的旧资源被覆盖或清空。
- A10：登录恢复与短期续期不投递成功 toast。持续连接故障用一个连接状态提示，不弹授权框，不刷屏。关于仅展示真实设备模型 ID、授权类别和机器授权到期时间。

## 状态迁移权限

授权状态：`checking` 待确认、`authorized` 已授权、`refreshing` 续期中、`reconnecting` 重连中、`required` 需要授权、`expired` 已过期、`revoked` 已撤销、`signed_out` 已退出。

前端只能自行提出 `checking`、`reconnecting`；`refreshing` 是统一刷新入口实际开始工作的内部状态，表现与原页面一致。所有授权成功/失败/终态由服务端响应确认。`signed_out` 只能由用户主动退出触发；离线退出应立即停止本地自动恢复，但不能声称服务端已撤销。

| 起点 | 终点 | 唯一允许的触发及证据 |
| --- | --- | --- |
| checking | authorized | 服务端确认现有凭证有效或续期成功 |
| authorized | checking / refreshing | 需要核验、临近短期期限或收到执行前鉴权拒绝；不能清空页面 |
| checking / refreshing | authorized | 服务端确认身份；迟到响应必须受请求代次约束 |
| checking / authorized / refreshing | reconnecting | 传输失败或服务不可达；保留身份及页面，不构造失效原因 |
| reconnecting | checking | 连接恢复后重新核验 |
| checking / refreshing | required / expired / revoked | 服务端明确返回无可恢复凭证 / 真实授权到期 / 撤销或授权替换；匿名 session 查询不能替代 refresh 结果 |
| 任意状态 | signed_out | 用户点击退出；本地停止恢复，服务端可达时撤销同一浏览器凭证族 |
| required / expired / revoked / signed_out | authorized | 用户主动提交新授权且服务端确认成功；验证期间保留原终态及授权表单，以提交中表达等待，失败不构造新终态 |

禁止绕过：401→授权页；本地期限→expired；重试失败→required；重启→revoked；signed_out→自动登录。收到已确认终态后，迟到刷新成功不得再次授权。所有其他迁移禁止。

业务状态独立：`unknown` → `confirming` → `ready` 或 `unavailable`。任何连接中断后回到 unknown。进入 authorized 后先 confirming；身份成功不能直接设置 ready。读取本机权威快照后才恢复操作。正常续期不打断已有健康业务；确实断线恢复必须重新核对。

| 业务行为 | 恢复权限 |
| --- | --- |
| 页面、草稿、列表、日志订阅 | 自动保留/恢复；标明待更新数据 |
| 运行/配置/设备/模型状态、已有预览订阅 | 自动重新查询或订阅；只呈现新确认结果 |
| 已成功执行的操作 | 查询结果，不再执行 |
| 重启后已经停止的采集、推理、输出 | 用户主动点击启动/启用；恢复身份不代为执行 |
| 执行对象变化、配置冲突 | 展示变化，由用户重新确认；普通重连不额外弹 dialog |
| 超时或未知结果的写请求、鼠标移动/点击等一次性指令 | 禁止自动重放，不跨断线存入执行队列 |

## 接口与持久化边界

沿用 `GET/POST/DELETE /api/auth/session`，增加 `POST /api/auth/refresh`。会话响应保持已有身份字段，增加服务端 `auth_state`、`server_time`、`license_expires_at`。GET 不续期，但已有访问身份须核对机器授权绑定；关于内用户主动更换授权使用同一授权入口，成功后立即同步新身份和双 Cookie，不能要求用户再授权一次；无短期凭证但有续期凭证返回 checking，客户端必须 refresh 后才判定 required。刷新暂时失败返回 5xx，不清除凭证；明确失效返回 required/expired/revoked，不用一个笼统 401 表示全部原因。

访问期限仍为一小时；绝对期限按原授权截断。使用项目已有签名库签发两个用途隔离的凭证；HttpOnly、SameSite=Strict Cookie，HTTPS 时 Secure，续期 Cookie 限定 `/api/auth`。服务端持久保存签名密钥、凭证族、原始授权绑定、期限、轮换代次及撤销记录；私有文件权限 0600、原子写入、失败不签发或确认轮换。不得在日志、URL、网页存储中记录授权码或 bearer 凭证。浏览器可保存不含凭证的主动退出标记。Cookie/JWT 的秒级运输时间可向上取整，服务端以原始精确机器期限执行授权，不能因此延长有效权限。新内测空码授予只保存原始申请时间；迁移的旧授予可保留代码摘要，原码在原期限内仍可使用。

轮换采用交付确认：仅观察到客户端提交当前代有效凭证，才确认新代已送达。确认前，上一代重试返回当前代，不因刷新响应丢失或服务重启而撤销；确认后兼容上一代 10 秒，同窗口当前代请求也合并，不再次轮换。越代或确认窗口之外的旧代复用拒绝并撤销该族。访问凭证可单独重新签发，但当前代续期凭证保持一致。多标签页共用同一浏览器凭证族，退出撤销该族；不同浏览器授权互不撤销。已有访问凭证在原有效期内仍可用，避免轮换导致在途业务请求失败；退出/真实授权失效必须阻断。

短时并发凭证协调优先用浏览器 Web Locks；不支持时共享 BroadcastChannel 通知并依赖服务端原子轮换/重复兼容。不能仅依赖单个页面的 Promise 冒称多标签页互斥。

源码已激活测试授权需要持久保存原始授予信息，普通 daemon 重启恢复原期限；正式授权激活或清除时必须清除该测试授予。持久数据不可读属于服务故障，不属于用户失效。过期授予不可因重启、GET 或 refresh 自动延长。内测版到期后允许用户再次主动空码申请新一天；正式版不接受空码。

## 内测空码申请与到期前提醒

- A11：版本权限由 daemon 服务端构建决定：Debug 为内测版，Release 为正式版，网页输入、请求参数和客户端样式不得切换版本。内测版允许 `POST /api/auth/session` 的 `key` 为去除空白后的空字符串；正式版后端返回 400 `LICENSE_KEY_INVALID` 和明确不可用原因，不签发 Cookie、不写入授予。缺少 key 或非字符串仍是无效请求。
- A12：新内测申请按服务端申请时间授予 24 小时并原子持久化；已有有效测试授予重复申请、不同浏览器申请和正常重启均保持原期限。原启动码授予迁移继续保留其原期限。到期后只允许用户主动再次申请；不会自动申请、续一天或启动资源。现有有效正式授权不能被空码覆盖。
- A13：在真实机器授权剩余时间进入 `(0, 3600]` 秒时，已授权的任意页面显示顶部 info toast，柔和信息色与通知图标，不使用红色、危险图标或阻断 dialog。隐藏标签页等待重新可见并核验后再提醒，静默错误设置不屏蔽此提醒。每个标签页对同一授权期限只提醒一次，页面切换、短期续期和刷新不重复；新授权期限允许新提醒。3 秒自动消失及匀速进度条沿用现有 toast。关于保留到期详情。
- A14：提醒以服务端确认的 `license_expires_at` 和 `server_time` 为准。本地阈值计时器只请求核验；恢复连接或休眠醒来后重新核验，若仍有效且不足一小时补提醒，若服务端已确认到期走原终态流程。连接失败不假称过期，不投递“即将到期”的确认提醒。正式授权同样提醒。

反向验证：①首次内测空码提交由用户触发，daemon 持久化申请时刻，网关签双凭证，页面进入原业务核对流程；②一天内空码重入/服务重启复用原期限，续期无感知；③前端提前一小时计时到达仅核验，服务端确认仍有效后发 info toast，业务继续；④正式版空码由 daemon 拒绝，停留授权表单说明原因；⑤真正到期资源停止，用户主动空码再次申请才生成新期限。没有前端终态判定或隐式自动授权。

新增验收 N1：内测空字符串及纯空白申请，期限从申请时刻计算；N2：并发/重复申请和重启不延长；N3：到期不自动申请、主动再申请有效；N4：正式版后端拒绝空码且不写盘；N5：不同页面/刷新/续期不重复提醒、阈值核验及休眠补提醒；N6：提醒为 info、通知图标、3 秒进度条，到期仍由服务端确认。沿用 S1–S8 作为回归边界。

参考：使用 [Arco Design 全局轻提示](https://github.com/arco-design/arco-design-skill/blob/main/skills/arco-design/references/components/feedback/message.md) 与 [Ant Design Message](https://ant.design/components/message-cn/) 的顶部、非阻断、info 语义。空码申请、一小时前提醒与去重期限为本项目产品要求，不宣称是抖音/阿里内部授权机制。

## 编码前反向验证

前提：同一真实授权尚未过期、未撤销，浏览器续期 Cookie 尚在，持久化完整。两小时休眠不能越过真实授权期限；越过期限时服务端确认 expired 是正确终态。

### 路径一：连续操作超过一小时

1. 服务端确认 authorized，用户处于原页，业务 ready。
2. 统一入口提前续期：前端请求 checking，入口进入 refreshing；用户看不到变化。
3. 服务端验证原授权和续期凭证，原子轮换，确认 authorized；期限仍被原授权截断。
4. 同时出现执行前 401 的请求共用刷新结果，各重试一次；不跳授权页，不重放超时写操作。

结果：无前端终态判定，无授权页。若网络故障转 reconnecting，不能跳 required。

### 路径二：电脑休眠两小时后恢复

1. 休眠前 authorized/ready；休眠期间计时器不是终态证据。
2. 可见性/focus 恢复或首个请求触发 checking，业务 confirming；原页面和草稿保留。
3. 短期凭证已过期，统一入口用仍有效的续期 Cookie；服务端确认 authorized，绝对期限不变。
4. 重新查询运行/配置/模型/设备状态；获得权威快照后 ready。停止的服务维持停止，硬件不自动启用。

结果：无前端终态判定，无授权页。若服务不可达，只进入 reconnecting；真实期限已过则由服务端确认 expired。

### 路径三：服务正常重启，浏览器一直开着

1. WebSocket/HTTP 失联触发 checking 或 reconnecting，业务 unknown；保留页面，不猜测后台已停止。
2. 服务恢复：加载原授权和凭证持久状态；测试授权也保持原授予期限，不能新发一天。
3. 客户端重新核验/刷新，服务端确认 authorized；用户不需要重新授权。
4. 查询新的 daemon 身份及权威状态，业务 confirming → ready/unavailable。新进程已停止的服务不自动启动。

结果：无前端终态判定，无授权页。若持久化故障则持续重连并显示服务异常，不构造 revoked。明确人工撤销或替换授权属于独立终态事件，不称为正常重启。

三条路径走通；发现的两个缺口（本地判过期、测试授予进程内存）已被 A02/A04 及接口边界纳入，必须实现后才能通过。

## 必须通过的八个场景

S1 连续超过一小时；S2 休眠两小时恢复；S3 断线重连；S4 服务正常重启；S5 真正授权到期；S6 并发请求同时 401；S7 多标签页同时使用；S8 写操作网络超时不重放。

时间推进测试允许使用受控时钟，不得将其描述为真实等待或硬件验证。后端 HTTP/持久化、前端状态/请求及浏览器交互均需证据；硬件停机证据单独记录。

## 参考事实与推导

“参考美团、阿里、抖音”对应持续登录、断线恢复和草稿保留这类产品体验目标。本契约不以未核实的公司内部机制为事实依据；零感知、迁移权限和硬件恢复边界均是本项目已确认的产品要求。关于这些公司具体实现的说法若无直接证据，只能标为推断，不能作为验收依据。

## 契约修订记录

- 编码前补齐 A02/A04：本地期限不得判终态，源码测试授予恢复原期限。
- P0-3：用户已处于授权表单时，新授权提交用提交中状态表达等待；失败保留已确认终态，避免传输失败自行宣布 required。
