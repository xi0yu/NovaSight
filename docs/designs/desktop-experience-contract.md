# NovaSight 桌面网页体验规范

适用范围：电脑浏览器中的登录、首页、采集、算法参数、开火稳定、鼠标协议、模型、实时日志、设置和关于。

本规范参考公开资料中的状态设计、反馈分级、组件一致性和感知性能。交互规则采用 NovaSight 的业务事实和用户已确认的偏好，视觉继续使用现有工作室主题。

## 参考资料与采用范围

- 腾讯 [TDesign Image](https://github.com/Tencent/tdesign-vue-next/blob/develop/packages/components/image/type.ts)：加载、占位、失败、备用图片和懒加载分别处理。
- 阿里 [Fusion Design](https://github.com/alibaba-fusion/next)：组件与不同页面的体验一致性。
- 阿里云 [交互反馈](https://help.aliyun.com/zh/document_detail/67475.html)：及时反馈、优先局部加载、慎用模态遮罩和多余确认。其小程序布局限制不直接作为桌面规则。
- 蚂蚁 [消息与反馈](https://ant.design/docs/spec/research-message-and-feedback-cn/)与 [Modal](https://ant.design/components/modal-cn/)：区分字段错误、轻提示、持续告警和必须决策的弹窗；管理焦点与键盘关闭。
- 美团 [感官性能实践（2017）](https://tech.meituan.com/2017/09/22/optimization-of-front-end-sensory-properties.html)：从用户可见的白屏、等待和资源加载分析体验。该文章不代表美团当前所有产品的实现。

## 页面和交互要求

| 维度 | NovaSight 要求 | 代码位置与审核结果 |
| --- | --- | --- |
| 首次加载 | 未读取配置时不显示可编辑的示例数值；提供同区块占位和读取失败后的重试 | `StudioConsoleView` 参数/开火稳定加载门控，本次补齐 |
| 局部刷新 | 保留已确认的数据和用户草稿；不因普通轮询替换整页 | `App` 请求序列与 `StudioConsoleView` 草稿同步，沿用 |
| 静态图片 | 保留区域尺寸，完整下载并解码后展示；失败保留占位；尊重懒加载与减少动画偏好 | `LoadedImage`，沿用已验证的实现 |
| 按钮 | 进行中可见、禁止重复写入；关闭、停用等状态用文字和图标说明 | `Button` 补齐加载图标；配置写入、协议操作已有防重入；日志清理补齐防重入 |
| 字段错误 | 错误贴近字段，关联辅助说明；提交错误聚焦首个无效字段；继续编辑清除过时错误 | `MouseProtocolView`，本次补齐 IP/Port/UUID 校验状态 |
| 参数保存 | 请求串行；旧回执不能覆盖新草稿；后端确认应用和写入后才提示成功；失败保留修改与重试 | 参数批量热更新及修订号冲突重试，沿用；加载前门控补齐 |
| 轻提示 | 顶部居中，成功/失败有图标、文字及红绿配色；3 秒倒计时，进度匀速 | `ToastHost` / `toast`，沿用时长；本次合并重复消息并重置对应计时器 |
| 持续故障 | 错误不能只依赖会消失的 Toast；保留字段/页面错误和日志中的排查编号 | 参数错误栏、协议错误、异常中心与 Activity，沿用 |
| 弹窗 | 打开时获取焦点，Tab 留在窗口内，关闭后返回发起位置；只有最上层处理 Esc；执行中禁止误关 | `useDialogInteraction`，本次统一配置、模型、确认、异常中心和加载弹窗 |
| 页面边界 | 设置/关于使用详细弹窗；协议配置留在协议页；参数未读取不阻断独立模型管理 | 原导航与页面边界沿用；失败状态模型管理入口补齐 |
| 导航上下文 | 返回页面保留草稿、筛选和滚动位置；浏览器前进/后退保留模型编辑保护 | 现有历史索引、草稿与滚动恢复，沿用 |
| 实时日志 | 新记录在顶部；阅读旧记录时暂停视图，接收继续；恢复显示新记录数量并回到顶部；可复制排查内容 | `ActivityView`，本次补齐滚动暂停、复制和 HTTP/剪贴板拒绝时手动复制 |
| 弱网与恢复 | 连接有超时和有上限的重连退避；保留旧内容并标记陈旧；恢复后不必等待业务事件才确认连通 | 状态流已有轮询/陈旧检测；日志流补齐连接超时和恢复显示 |
| 桌面键盘 | 输入框、菜单和按钮可按 Tab 操作；表单可按 Enter 提交；弹窗支持 Esc；错误和状态不只靠颜色 | 原生控件及弹窗键盘回归，沿用并统一 |

## 反馈分级

- 正常保存、切换协议等用户明确要求提示的操作，使用 3 秒 Toast。
- 相同来源、等级、标题、正文及状态码的当前可见 Toast 合并为一条，显示次数；从最后一次发生开始重新计算 3 秒。不同结果不能合并。
- 异步后台异常保留在异常中心和日志，不反复弹窗。
- 输入错误保留在对应字段；保存、读取、握手失败提供原地重试或可执行的下一步。
- 二次确认用于可能丢失草稿、删除、配置恢复和影响实际运行的操作；普通参数热更新不新增确认。
- 模型切换等后端无法安全取消的事务显示真实阶段及等待回执，不提供只关闭窗口却宣称取消了任务的按钮。

## 实现边界

- 新弹窗逻辑沿页面层级对弹窗外的普通工作区及下层弹窗使用可叠加的 `inert` 引用计数；紧急停止工具栏保持可操作。
- 弹窗打开期间，运行状态更新和回调变化不能抢走用户正在编辑的输入焦点。
- 协议留空默认值、空协议静默输出、授权期限及物理输出确认继续按现有业务规则执行。
- 剪贴板采用浏览器 Clipboard API。HTTP 或权限拒绝时展示并选中文本，让用户按 Ctrl+C / ⌘C 复制，不关闭浏览器的保护设置。
- 静态图片的完整展示不改变 MJPEG 实时画面的播放逻辑。
- 保持现有 React/CSS 和内部组件，不为参考设计体系新增整套 UI 依赖。

## 验收方式

自动化检查覆盖真实配置到达前的占位、失败后重读、重复 Toast 的数量和计时、字段纠错、弹窗叠层/忙碌/焦点保持、日志暂停/恢复/复制、连接停滞后的恢复，以及已有主要页面和窄屏流程。

验证命令：

```sh
pnpm --dir web test:ci
pnpm --dir web test:e2e --workers=2
pnpm --dir web build
pnpm --dir web visual:audit
```

真实远程网络波动、人工视觉走查、系统剪贴板实际写入、读屏软件及物理硬件运行需要分别验证。自动化延迟响应和模拟剪贴板不是这些实测的替代品。

远程当前使用源码开发入口。生产首屏性能应以打包后的静态资源另行测量；开发服务器的响应时间不作为生产性能结论。
