# NovaSight Studio 前端体验成熟度检查（2026-09-26）

范围：当前 Studio 的授权入口、首页、设备管理、模型管理、算法参数、实时日志、关于及资源页。检查了源码、离线 API 的桌面/移动浏览器流程和现有测试；**没有把模拟 API 当作 Jetson 实机验证**。

## 用户体验的底线

每个展示值必须带着可判断的来源状态：`正在读取 / 当前已核实 / 已过期 / 读取失败 / 确实为空`。这些状态不能共用一个“0”“正常”或“已生效”。会影响设备的操作，既要有清楚的单一入口，也要在提交前说明物理后果；提交后给出等待、生效或失败及原始错误。关键入口和安全控制不可被动态页面配置隐藏。

## 尚未完成，不能对用户承诺

1. **“实时日志”不是真正的后端日志。** 目前列表由本次会话的错误与前端操作通知合成（`StudioConsoleView` 的 `activityItems`），没有 daemon 日志流、跨会话历史或稳定的 tag/严重度来源。要满足“Web 比命令行好用”，需要后端结构化事件接口、保留策略和前端断线补拉；仅改颜色无效。
2. **首页缺 CPU、内存、GPU、温度、电压的可信指标。** 当前前端运行态没有这些字段；不能制造装饰性数字。需要明确采样端、时间戳、单位、可用性、刷新频率，再做图示。
3. **页面运营配置只是静态 JSON 轮询，不是运营后台。** 现有 `/studio-layout.json` 可重排部分模块，但缺发布、预览、权限、回滚和错误可见性。不能称为“无需客户端更新的完整动态配置”。
4. **配置错误仍被静默回退。** `useStudioLayout` 忽略请求失败/解码错误；虽然保住了页面，却不给管理员解释为什么布局没有生效。应增加配置诊断记录，不把每 30 秒的相同错误重复弹给普通用户。
5. **算法参数仍是“修改→保存并应用”，并非真正修改即生效。** 当前保存栏明确如此，输出开关另行确认是安全边界。若要实时调参，需后端逐字段热更新能力、回执和失败回滚；不能靠前端自动提交伪装。
6. **主视图仍集中在一个 6600 行组件。** 运行、设备、模型、参数及错误状态交织，增加交互回归风险。下一阶段按用户任务拆容器与状态归属；不为了文件数量机械拆分。

## 下阶段验收门槛

- 每页都能在加载、无数据、失败、过期、当前有效五态说真话；用 API 模拟测试覆盖两种视口。
- 每个主操作在点击后有进行中、成功、失败三态，失败就在操作附近说明恢复方式；原始错误仍可展开。
- 任何硬件输出或运行操作都要求当前证据和明确用户动作，不能被页面配置隐藏或因热更新自动开启。
- 为真实指标和日志先补后端数据契约与时间戳，再设计视觉组件；未接入前直说“暂不可用”。
- 在 Jetson 上走一次授权→采集→模型→参数→启动→断线→恢复的实机回放；浏览器模拟通过不等于设备验收。
