## P1：优先修复

### 1. 会话失效、重新登录后，未保存参数丢失

- **证据：浏览器确认 + 代码确认。** 在正式应用入口的模拟 API 中，将搜索半径从默认 `180` 改到 `320`，确认出现未应用修改栏；触发 `novasight:auth-required`，重新登录后值恢复为 `180`，修改栏消失。
- **位置：** `web/src/features/auth/AuthGate.tsx:100`、`:117`、`:175`；草稿存于 `web/src/features/studio/StudioConsoleView.tsx:786`。
- **原因：** 会话失效后切换到登录分支，整个 Studio 被卸载。刷新/关闭页面的 `beforeunload` 保护不能保护 React 内部卸载。
- **影响：** 用户调参期间遇到会话过期或认证失败，会失去尚未提交的工作。
- **建议：** 认证失效时锁定操作，保留未提交编辑；恢复身份后重新读配置并核对版本，再允许用户选择恢复草稿。不能为了保留草稿自动保存到设备。
- **建议命令：** `$impeccable harden`。

### 2. 已实现的紧急停止流程没有接入正式页面

- **证据：代码确认，浏览器主页面入口检查一致。** `useMainlineLaunch` 返回 `emergencyStop`、`emergencyStopping`，但 Studio 只取得 `start` 和 `stop`，没有紧急停止按钮。正式页面也没有调用该方法的入口。
- **位置：** `web/src/features/studio/useMainlineLaunch.ts:318`；`web/src/features/studio/StudioConsoleView.tsx:2233`；普通关闭流程 `:2422`。
- **影响：** 调参、模型或设备页面上没有直接停止入口，需要返回首页；首页总开关还会在进行中、运行状态不可用时禁用。现有独立紧急停止及回执能力无法从该页面触达。
- **建议：** 将已有紧急停止方法接到固定、可识别的入口，保留现有请求与安全快照确认流程；不能把普通停止的点击结果直接显示为紧急停止已确认。
- **限制：** 本次没有发送停止请求，不能判断实机上的停止耗时或物理效果。
- **建议命令：** `$impeccable harden`。

### 3. 模型管理缺少稳定、可发现的日常入口

- **证据：浏览器确认 + 代码确认。** 当前设备管理页只有采集设备、画质和 ROI；主导航没有模型页。顶部已有模型入口被 `.console-context-deck { display: none; }` 隐藏。新手引导里的“选择模型”是替代路径，但引导入口在窄屏和高度不超过 700px 时隐藏。
- **位置：** `web/src/contracts/studioLayout.ts:1`；`web/src/features/studio/studio-navigation.css:85`、`:321`；`web/src/features/studio/StudioConsoleView.tsx:3387`；`web/src/features/studio/ProductJourneyViews.tsx:115`。
- **影响：** 未配置时可由首页下一步进入模型页；已经配置完成后，用户想再次换模型却难以发现入口。运行中首页角色入口指向设备状态，并非模型管理。
- **建议：** 在设备管理中保留“当前模型 / 管理模型 / 查看识别”的明确入口，复用已有模型工作区和推理页，不需要增加一个新页面。
- **建议命令：** `$impeccable onboard`、`$impeccable clarify`。

### 4. 采集 ROI 示意图文字与背景同色或对比度过低

- **证据：浏览器计算样式确认。** 背景为 `#353344`；`640 × 640` 数值也是 `#353344`，对比度 **1.00:1**。源画面说明为 `#746979`，约 **2.36:1**；“模型识别区域”为 `#655c70`，约 **1.94:1**。这些文字均为 11–13px。
- **位置：** `web/src/features/studio/studio-settings.css:267`、`:276`、`:285`、`:317`。
- **影响：** 用户看不清源规格、区域尺寸和区域含义，核心尺寸数值实际上不可读。未达到普通小字 4.5:1 的对比度基准。
- **建议：** 给该深色区域使用合适的浅色前景 token，分别核对数值、说明及状态文字。不能只把字体加粗。
- **截图：** [采集页](../../out/ux-audit-2026-10-09/capture-1366.png)。
- **建议命令：** `$impeccable colorize`。

### 5. 日志历史读取失败、日志流断开，没有日志自己的状态反馈

- **证据：代码确认 + 模拟 API 失败观察。** 历史请求错误被 `.catch(() => undefined)` 吞掉；Hook 只返回 `events` 与 `clear`，没有加载、失败、断开、过期状态。模拟 `/api/activity` 返回 503 后，页面没有日志通道失败提示，只能看到其他运行/schema 请求造成的故障。
- **位置：** `web/src/features/activity/useActivityStream.ts:22`、`:31`、`:60`、`:82`；`web/src/features/activity/ActivityView.tsx:73`、`:141`。
- **影响：** 若只有日志通道失败，用户无法区分“确实没有记录”与“没有读取到记录”；有旧记录时也不知道其是否继续更新。
- **建议：** 单独显示日志读取及实时连接状态。首次失败提供重试；旧列表保留并标记停止更新。不要由主运行态连接正常推导日志流正常。
- **说明：** 当前后端在 WebSocket 连接时会发送已有历史，本次没有把“重连必然漏掉全部历史”列为问题；也没有把旧报告中的“没有后端日志”沿用为现状。
- **建议命令：** `$impeccable harden`。

## 系统性原因

1. **状态模型没有贯穿所有组件。** 运行态已有当前/过期/不可用，日志却仍主要由空数组表达状态；开火稳定把草稿值表述成已开启。
2. **入口隐藏与任务归属不一致。** 模型页保留了实现，却没有在其归属的设备管理里留下稳定入口；后台紧急停止能力也没有正式页面入口。
3. **多页共享编辑状态，文案仍按单页描述。** 草稿共享可避免切页丢失，但保存和放弃必须说清影响范围；认证失效又会绕过这套保护。
4. **全局样式与局部主题缺少约束。** 深色区域沿用浅色文字 token；全局文本换行与狭窄筛选按钮共同造成内部布局错误。

## 当前已做好的部分

- 未读取运行态时明确“无法确认运行状态”，不会再展示首次设置完成数；过期状态禁用运行操作。
- 模型目录读取失败与确实为空分开显示，重试入口存在，未知目录不允许新建文件夹。
- 参数页有统一保存栏、未保存提示和关闭页面保护；模型标签退出有放弃确认；保存失败保留编辑。
- 已实现后端日志历史与实时流，不再只是前端 Toast 汇总；列表可搜索排查编号并展开原始详情。
- 标签页支持左右方向键、Home、End；弹窗已有焦点限制；多处响应式和减少动画规则存在。
- 上述 24 个主页面样本未发生页面脚本异常，也没有整页横向溢出。内部布局、状态和数据保留问题仍需单独验收。
