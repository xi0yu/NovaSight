# NovaSight 前端修复与验收记录（2026-10-09）

修复基于 `develop-alpha`、HEAD `99f98b34`。本次修改尚未提交、推送或部署。原问题清单见 [前端体验问题清单](studio-ux-audit-2026-10-09.md)。这里记录修复后的行为；旧清单中的截图和行号是修改前的证据。

## 用户新增要求

### kmBox 配置与测试

主导航增加独立 **kmBox** 页面，设备管理页增加“配置与测试 kmBox”入口。页面集中展示地址、UUID、控制端口；按键监控端口放在高级设置中。完整配置在编辑结束后自动保存，失败保留输入并提供重试。运行时占用设备会话时锁定连接修改与测试，并说明关闭首页运行开关后继续。

“测试连通性”通过新的后端命令进行实际设备 `connect` / `disconnect` 握手。成功展示耗时、测试时间和测试会话已断开的状态。失败连接也执行清理。它不启动采集、不打开输出门、不发送位移，且不会清除紧急停止后的设备不可用标记。真实物理位移诊断收进高级区域，只保留一次测试移动和必要参数，继续需要明确确认。

### 参数自动保存和生效

算法参数、类别配置与开火稳定共用自动保存流程：编辑提交后合并 350 ms 内的修改，串行发送批量参数更新。滑块在松手、键盘提交或离开控件时提交；输入框在结束编辑时提交，避免输入过程的中间值写入设备。

每次批量更新都有 revision 校验；遇到冲突重读并重放本次字段一次。运行时通过 Supervisor 安装参数，不重启主链。配置文件使用原有文件锁、校验、安全元数据保留和原子替换机制，一批字段只增加一个 revision。类别映射采用完整字段替换，删除旧配置时不会残留旧 map 条目；内部设备配置与 YAML 校验标记保持完整。

保存期间可以继续编辑。旧请求回执只提交它自己的修改，之后的编辑重新基于新 revision 排队。未取得 `hot_update / applied / !rolled_back` 回执时保留草稿和错误，提供重试。运行时应用失败会恢复旧参数并补偿文件保存；恢复失败时关闭输出门并标记配置与运行状态不一致。

日常参数已移除手动保存与保存确认框。成功显示顶部居中的绿色 Toast，失败显示红色 Toast；失败提示保留到关闭，并保留诊断记录。操作结果反馈在静默后台错误模式下仍显示。Toast 正文支持点击穿透，关闭与排查信息继续可交互。

采集规格、ROI 重载、模型部署、配置导入及实际物理位移属于重建运行资源或启动输出的操作，继续使用各自的校验和必要确认。

### 对外库与接口

复用并扩展现有 `novasight-config`、`novasight-runtime` 和 `novasight-client`，无需新增依赖。

| 接口 | 职责 |
| --- | --- |
| `YamlConfigRepository::save_fields` | revision 校验后的原子字段批量保存；`None` 删除可选字段，`Some` 替换完整字段 |
| `AppConfig::with_control_parameters` | 生成参数候选配置，保留 API 序列化省略的适配器字段与校验信息 |
| `ConfigService::update_parameters(&runtime, update)` | 参数校验、文件保存、运行时安装与失败补偿的统一入口 |
| `RuntimeHandle::probe_device()` | 停止状态下的无位移设备握手测试 |
| Rust 客户端 `update_parameters(update, acknowledged)` / `probe_device()` | 对上述 HTTP 接口的类型封装 |
| 前端 `updateRuntimeParameters(changes, revision)` / `probeKmNet()` | 请求、输出确认头和严格响应解码的统一接口 |

HTTP 参数入口：`POST /api/v1/config/parameters`，示例：

```json
{
  "expected_revision": 25,
  "changes": [
    { "section": "pipeline", "key": "p_response_scale", "value": 0.7 },
    { "section": "control", "key": "fire_stabilization", "value": { "enabled": true, "strength": 0.5 } }
  ]
}
```

允许 1–64 个不重复字段：已知 `pipeline` 参数，`control.aim`、`control.fire_stabilization`，以及类别名称、优先级、过滤器和自定义预设元数据。可选字段可用 `null` 删除；必需字段仍须满足配置校验。运行开关、触发模式与硬件连接不通过该参数接口写入。成功返回现有 `ConfigUpdate`，其中 `apply_mode=hot_update`、`applied=true`；其他待重启配置继续如实标记 `restart_required`。

HTTP 测试入口：`POST /api/executors/kmnet/probe`，无需位移参数，返回 `reachable`、`elapsed_ms`、`checked_at_ms`。浏览器请求继续由现有登录会话、CSRF 和权限边界保护；参数修改需要 `configuration:write`，设备测试需要 `hardware:operate`。现有物理输出确认协议仍在后端执行，前端对用户主动提交的参数修改自动发送确认头。
