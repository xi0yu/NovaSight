# NovaSight 前端产品体验评审（2026-10-09）

## 结论与范围

本轮由独立的产品经理视角评审代理审阅当前源码与最新界面，主代理复核了关键调用链、函数重放结果和 375×812 的实际浏览器界面。评审代理不是外部人类产品经理，也未进行真实用户访谈。

面向两类任务：第一次配置采集、模型、参数与输出的使用者，以及日常运行、调参、检查连接和恢复配置的使用者。发现 1 项优先处理的运行/停止语义缺陷，以及 7 项流程或可发现性优化。建议实施顺序：先纠正运行状态与停止回执，再改善连接测试和首次引导，随后处理运行中只读查看、协议清理、恢复差异和手机入口。

沿用已确认的设计：鼠标协议在业务菜单最后；设置/关于位于桌面底部并打开弹窗；协议主页面只有卡片格栅和新增按钮；卡片维持 320/256 方形及 95% 图片/5% 文字；继续使用官方实物图与可爱容器；空协议是合法的静默消费端；留空使用提示默认值；启用/取消控制实际对象；参数自动应用保存，操作提供红绿 Toast。已修复的边框、Toast 挂载、导航与弹窗职责不重复列为缺陷。

## 推荐修改清单

### 1. P1：把“输出安全”和“主链已停止”分开

**当前问题。** 后端空协议即使主链运行，也将输出标为 safe、daemon_confirmed_safe=true，这是静默消费的安全语义。前端却把同一标志解释为系统停止、设备断开、输出门关闭。设备状态页也固定使用 kmNet 连接文案。

**用户影响。** 默认空协议运行时，首页可能同时显示“运行中”和“系统已停止”。停止回执处理也复用该标志，因此影响不止文案。

**已核实的重放。** 执行未修改的 projectRuntimeState，构造 phase=running、output.state=safe、reason_code=null_mouse_protocol、daemon_confirmed_safe=true，返回生命周期“运行中”，结论却为“系统已停止并确认硬件输出安全”。用最小 React hook 替身暴露未修改 SafetyOperationProvider 回调，重放同 daemon 的请求序列 100 与仍 running 的新快照 101，停止回执返回 confirmed，宣称主链停止。该证据属于生产函数/回调重放，不是浏览器连接真实 daemon 或硬件复现，也不表示物理设备仍在输出。

**推荐修改。** 保留空协议输出安全保障；独立核验主链停止，普通/紧急停止回执要求生命周期已停止，并保留 daemon 身份、快照序列和因果核验。首页显示“主链运行中 · 空协议静默输出”，设备状态使用实际消费端；“已启用”与“已连接”各用自己的证据。当前预览的 running-target 分支将输出模拟为 blocked，未覆盖真实空协议 safe 分支，应补对应状态组合。

**验收。** 空协议运行时不出现“已停止”；仅输出安全且仍 running 的新快照不能确认停机；停止且安全的快照仍能确认；真实硬件状态保持原有安全检查。

**证据。** crates/novasight-api/src/dto/runtime_status.rs:1276、1303；web/src/features/runtime/runtimeProjection.ts:38、118、132；web/src/features/runtime/SafetyOperationContext.tsx:53；web/src/App.tsx:317；web/src/features/studio/useMainlineLaunch.ts:33、193、267；web/src/features/studio/ProductJourneyViews.tsx:227。重放记录见 ../../out/product-manager-review/runtime-null-projection-replay.json。

### 2. P1：连接测试应支持“填写 → 测试 → 启用”

**当前问题。** 新增弹窗没有测试入口；只有当前启用协议允许握手测试。未启用协议的编辑弹窗虽然有测试按钮，但不能使用，也没有解释原因。

**用户影响。** 用户必须先改变实际输出对象，才能判断新配置是否连通，排错时难以保留原来的可用协议。

**推荐修改。** 短期在弹窗说明测试条件，并给出明确启用入口；完整方案让测试接口接受候选协议，建立临时会话、测试并断开，保持当前启用对象。仍要求主链停止，仍不发送位移。候选配置测试涉及后端接口设计，不能仅让前端按钮看起来可用。

**验收。** 未启用候选协议能在停止状态完成或报告握手失败；无论成功失败，原启用 ID、运行对象和保存配置不被测试改写；没有移动输出。测试结果清楚区分握手通过与持续在线。

**证据与限制。** MouseProtocolView.tsx:80、135、151；StudioConsoleView.tsx:2649、2662。资格限制由当前源码确认；预览按设计禁用所有真实设备测试，不能用预览禁用状态证明硬件不可连。

### 3. P2：运行中仍可查看配置，并说明禁用原因

**当前问题。** 运行中新增、编辑、启用/取消全部禁用。原因只放在 title，手机实际界面没有可见说明，用户也无法打开已有协议查看 IP/Port/UUID。

**推荐修改。** 允许打开只读配置；在弹窗显示“主链运行中，停止后可修改”及前往首页入口。卡片内部提供短状态提示，维护主页面的简洁。修改、切换、保存和真实测试继续受停止状态约束，不自动帮用户停机或重启。

**验收。** 手机不用长按或悬浮即可理解限制；运行时可只读查看；切换和写入仍被前后端拒绝。

**证据。** MouseProtocolView.tsx:42、54、65；实际手机截图 ../../out/product-manager-review/mobile-running-protocol.png。浏览器读取到三个按钮均 disabled，title 均为“主链运行中，请先关闭首页运行开关。”，画面没有该说明。

### 4. P2：首次引导明确当前输出，并修正完成度含义

**当前问题。** 引导只有连接画面、选择模型、确认参数、开始运行；没有介绍输出选择或默认空协议。“确认参数”完成条件实际是配置 revision 同步，不能证明用户已经检查参数。

**推荐修改。** 配置一致性使用“参数已同步”这样的准确名称。开始运行前明确“当前输出：空／具体协议”，解释空协议不会发送物理鼠标指令，并提供可选“选择鼠标协议”入口。空协议继续合法，不强迫用户启用硬件。

**验收。** 新用户能说明当前输出目的地；知道静默运行也可以用于验证采集/推理；进度不会将版本一致表述为已经由用户确认参数。

**证据。** ProductJourneyViews.tsx:59、94、104；StudioConsoleView.tsx:3336。手机首页截图 ../../out/product-manager-review/mobile-home.png；初始页面已有“首次设置 · 1/4”，但未展示当前输出。

### 5. P2：协议需要去重与清理路径

**当前问题。** 连续留空新增会生成不同 ID、相同型号及连接字段；保存按 ID 追加，无相同连接去重。没有删除入口，最多允许 64 条。相同型号/IP 的卡片文字无法区别这些记录。

**推荐修改。** 相同完整协议再次新增时定位现有卡片并提示。在编辑弹窗增加删除未启用协议的入口；当前启用协议先取消再删除。继续保留默认值回退、官方图片和现有卡片布局，主页面无需增加工具栏。

**验收。** 相同协议不会无意堆积；非启用记录可清理；删除不影响正在使用的对象；达到数量上限时说明原因及处理入口。

**证据与限制。** MouseProtocolView.tsx:14、55、69、91、118；StudioConsoleView.tsx:2641。代码确认重复与清理缺口，未推断真实用户的设备数量或修改实际配置。

### 6. P2：恢复配置确认展示具体前后差异

**当前问题。** 界面承诺先预览改动，确认弹窗却只列 changedSections 的区块名。

**推荐修改。** 保留现有一次恢复确认，增加可折叠字段差异，优先展示采集规格、启用协议、连接目标、控制参数及需要重启的基础项；敏感凭据遮罩。保留 revision 复读、CAS、串行保存、失败补偿与物理输出保护。

**验收。** 用户确认前能知道哪些关键值会被替换、哪些立即生效、哪些等待重启；取消不写入；差异和确认使用同一最新 revision。

**证据与限制。** SettingsView.tsx:63；StudioConsoleView.tsx:3106–3119。源码与既有截图确认信息粒度；本轮未执行配置恢复。

### 7. P2：手机端提供固定可见的应用菜单入口

**当前问题。** 375px 手机首页只能看到首页、设备管理、算法参数；设置按钮范围 x=771–879，关于 x=888–996，均在首屏之外。侧栏可横向滚动但滚动条隐藏，功能存在不等于容易发现。

**推荐修改。** 手机将设置/关于收进固定可见的“更多”入口，并保持弹窗行为；桌面底部位置、业务排序保持既定设计。业务菜单可增加轻量边缘滚动提示。

**验收。** 手机首屏能够发现应用菜单；无需猜测横向滑动才能找到备份、版本与授权入口；业务导航不产生整页横向溢出。

**证据。** StudioNavigation.tsx:123、150；studio-navigation.css:336；实际手机 DOM 测量与 ../../out/product-manager-review/mobile-home.png。

### 8. P3：备份下载提供准确反馈与可识别文件名

**当前问题。** 导出创建链接后结束，没有统一操作反馈；文件名始终是 novasight-config.json。

**推荐修改。** 文件名附日期/时间和 revision；投递“已发起备份下载”的绿色提示。提示表述下载已发起，不宣称浏览器已经完成落盘。

**验收。** 连续备份容易区别；点击后有反馈；文件仍来自已保存配置，未保存草稿不会混入。

**证据与限制。** StudioConsoleView.tsx:3085–3098；SettingsView.tsx:49。未触发下载、读取用户文件或验证浏览器落盘。
