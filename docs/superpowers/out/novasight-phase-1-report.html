这次重建解决的问题

原始问题
原项目长期叠加模型配置、算法选择、硬件控制和 Web 结构，导致输入尺寸、类别名、 模型文件、控制策略和运行状态难以区分。
核心选择
不再把模型和算法塞进一个全局配置；模型进入 SQLite 仓库，算法进入插件协议， 控制动作通过执行器边界输出。
交付形态
一个 Python FastAPI 后端、一个 React/Vite 管理控制台、一套测试覆盖，以及可继续迁移旧算法的插件接口。

架构结果

运行时边界

novasight/runtime 只关心实时帧、部署模型、插件执行和控制意图流转， 不承担模型上传、转换或发布职责。

模型仓库

novasight/model_registry 用 SQLite 管理项目、版本、artifact、转换任务和部署状态； 模型资产默认位于 data/models。

插件与执行器

视觉分析插件返回结构化分析结果；控制插件只返回 ControlIntent； dry_run 是默认执行器，kmnet 作为可选硬件适配。

已完成内容

Task 1

项目脚手架

建立 pyproject.toml、Python 包结构、CLI 入口、忽略规则和 README， 让项目可以从空目录以标准方式运行和测试。

Task 2

运行时 YAML 配置

添加 config/novasight.example.yaml 和 runtime config dataclass， 只保存端口、日志、数据目录、默认 source、帧限制和执行器等运行时字段。

Task 3

SQLite 模型注册表

实现模型项目、版本、artifact、转换任务、部署和回滚。重点补强了路径约束、 JSON 读取、状态迁移和 artifact 生命周期校验。

Task 4

插件和执行器运行时

建立视觉插件、控制插件、执行器协议，以及内置 vision.track_stats、 control.center_target、dry_run、kmnet。

Task 5

管理 API

暴露健康检查、运行状态、模型仓库、插件、执行器和 frame flow 相关接口， 并强化错误返回、排序确定性、SQLite 可移植性和活动部署约束。

Task 6

React 管理控制台

实现 Dashboard、Live View、Models、Plugins、Settings 五个工作视图。 UI 以操作台为目标，避免营销页式布局，并加入资源加载失败提示。

Task 7

文档与运行说明

更新 README 和 Superpowers 设计、计划文档，记录本阶段的边界、运行方式和验证命令。

主要文件和职责

路径 职责
novasight/config/runtime.py 运行时 YAML 的加载、保存和字段校验。
novasight/model_registry/store.py SQLite schema、模型版本、artifact、转换任务、发布与回滚。
novasight/plugins/contracts.py 视觉分析结果和控制意图的协议定义。
novasight/runtime/service.py 连接 frame context、插件执行和 executor 输出。
novasight/api/app.py FastAPI 应用工厂和路由装配。
web/src/App.tsx 管理控制台的主界面、视图切换和状态呈现。

当前边界

Phase 1 是可运行的管理与插件化底座，不是完整生产视觉算法迁移。旧项目中的 v3、straight、chris、sunset 等算法应在后续阶段按新插件协议迁移，不能继续依赖全局配置或直接调用硬件接口。

建议下一步

迁移真实算法

先选一个视觉分析算法和一个控制算法作为样板，按插件协议迁入， 为后续算法建立输入、输出和配置模板。

接入真实帧流

把当前 runtime frame flow 对接 Jetson 摄像头或视频源，补齐帧推送、检测框和 UI live view。

TensorRT 转换闭环

在 Jetson 环境实现实际转换命令、日志采集和失败诊断，让模型仓库从记录层进入生产流程。
