# Studio 信息展示归属

目标：Studio 默认界面服务正常用户的启动、观察、调参和停用；累计计数、协议回执、generation、原始诊断和内部证据只在排障时展开。

## 展示原则

1. 当前页只放该场景的主操作和当前状态，不把后台链路证据铺在首屏。
2. 同一个事实只在一个主位置展示；其他页面需要时只给状态摘要或折叠诊断。
3. 配置页展示用户能调的参数和保存/运行是否一致，不展示流水账式遥测。
4. 控制页展示预测-控制-限制-输出链路是否通过；细分字段用于诊断，不作为正常用户的主内容。

## 运行状态流契约

- Studio 只使用 `GET /api/studio/v1/status` 与 `/ws/studio/v1/status` 读取同一份完整状态，不再按页面切换 topic。
- `novasightd` 负责给出生命周期、就绪原因、感知新鲜度、输出安全结论和建议动作；前端只翻译标签、导航到对应页面，不解析错误文本重新判定业务状态。
- Studio 通过 `PUT /api/studio/v1/runtime` 提交 `running` / `stopped` 意图，通过 `POST /api/studio/v1/runtime/emergency-stop` 急停；每次控制都返回权威运行状态。
- `/api/runtime/*`、`/api/v1/runtime/*` 与 `/ws/status` 暂留给已有脚本和兼容客户端，不再作为 Studio 主接口。

## 责任边界

| 责任 | `novasightd` | Studio 前端 |
| --- | --- | --- |
| 采集、推理、跟踪、预测、安全与 kmNet | 执行并持有唯一状态 | 不执行、不复制状态机 |
| 是否可运行/停止、输出是否安全 | 计算并通过 `presentation` 返回 | 按结论启用控件和显示状态 |
| 下一步处理建议 | 返回稳定动作码 | 把动作码映射到现有页面 |
| HTTP / WebSocket 断线与过期 | 提供快照序号和心跳 | 只判断传输可信度，不改写业务结论 |
| 页面布局、文字、导航 | 不负责 | 唯一负责人 |

| 模型推理 | 推理 FPS、结果 FPS、结果新鲜度、最近检测、当前模型、模型装载状态、置信度/NMS 配置、ROI 输入预览 | nvinfer 输入/输出计数、DetectionBatch 发布/消费、PTS 匹配、generation、模型输入细节、后处理输出证据 | 运行置信度/NMS 不再在模型工程详情里重复出现 |

| 设备测试 | kmNet 连接、执行器可用、按键数据、自动连接、诊断移动按钮 | 累计接受、恢复/错误计数、协议回执 | 累计计数只用于排障，不作为当前控制质量指标 |
| 延迟分析 | 延迟阶段、结果帧龄、结果 FPS、统计窗口 | 深度阶段计数和窗口细节 | 不把延迟页的信息重复搬到采集/推理/控制首屏 |

## 后续清理队列

- 控制页的七阶段实时链是唯一首屏摘要；目标筛选、输出和设备回执的内部证据只在诊断详情中展示。
- 参数页不放独立摘要指标条；配置画像、输出门、预测开关和配置入口本身就是主内容。
- 主题适配要以同一批控件令牌为准，优先修正按钮、开关、折叠区、输入控件在不同主题下的对比度。
- 参数控件继续从“输入框 + 按钮”迁移到分段控制、开关、滑杆、预设和高级折叠，但保持同一运行方式和同一配置语义。
